# Trollcraft III: notes for Claude

Server-admin work for the **Trollcraft III** modpack: KubeJS scripts, progression research and the server's story.

## The pack and server
- Minecraft **1.20.1**, Forge **47.4.10**, KubeJS **2001.6.5** (KubeJS 6, Rhino script engine). Hosted on Bisect.
- About 198 mods. Their progression is documented in [PROGRESSION_MODS.md](PROGRESSION_MODS.md), [MOD_TIERS.md](MOD_TIERS.md), [STARTING_MODS.md](STARTING_MODS.md), [CROSS_REFERENCE.md](CROSS_REFERENCE.md) and [PROGRESSION_GATES.md](PROGRESSION_GATES.md). The last one lists each mod's item ladder and its bypass routes.
- ProjectE has been removed from the pack, along with AppliedE and Tinkers' EMC (which needed it). The Nether is locked until the Pig Escort succeeds.

## The story
**[STORY.md](STORY.md) is the source of truth** for the server's two-part story ("Technoblade Never Dies"). It holds the series of events, which systems are built, the build order, and the open decisions. Read it before story or event work, and keep it updated as decisions are made and things are built. [PART2_SCRIPTS.md](PART2_SCRIPTS.md) says which Part I scripts carry into Part II, need adapting, or go.

## Layout
- `tools/kubejs/server_scripts/`: server scripts, in the same folders on the server (`kubejs/server_scripts/...`).
  - `economy/`: `black_market.js` (Hush Coins, the Hooded Merchant, contracts, traps, pranks, Tracker Compass, Homing Pig, Certified Alibi), `bounties.js` and `trolls.js` (the Troll Log; `global.Trolls`). The Blood Pool is saved for Part II.
  - `factions/`: `factions_config.js`, `factions_core.js` (`global.Factions`), `portal_ambush.js` (ambushes, raids, "no getting away"; `global.PortalAmbush`) and `trials.js` (`global.Trials`).
  - `story.js` (Part I's acts and decrees; `global.Story`); `clean_slate.js` (the finale countdown, started by the first dragon kill; `global.CleanSlate`); `events/blood_portal.js` (Blood Relics, Archive books, the Blood Portal event; `global.BloodPortal`); `end_lockdown.js` (the End Lockdown Initiative; `global.EndLockdown`); `events/pig_escort.js`; `techno_tribute.js`; `smite.js` (`/smite`, `/aura`, `/superaura`); `ministry_broadcasts.js`; `disguise.js` (`/disguise`: an op appears as any name and skin; `global.Disguise`); and smaller scripts.
  - `part2/`: Part II only (not for the Part I server). `blood_pool.js` (the Blood Pool, its 12 tiers and the Potato Tithe, plus Techno's Potato War: each player's Potato Standing, raised by `/potatowar offer`, gates crafting-table recipes for players via a `modifyResult` check on KubeJS stages `potato_standing_<n>` (autocrafters craft freely, but placing one needs its tier's rank) and the black market's `STANDING_LOCKS`; `global.BloodPool`; the open tier is also kept in `kubejs/blood_pool_tier.json` for the recipe step), `dimension_gates.js` (the Nether opens at Tier 3, the End at Tier 9; `global.DimensionGates`) `blood_tank.js` (a tower that fills with blood, one layer per 2 tiers; `global.BloodTank`) and `potato_tree.js` (the Potato War upgrade tree: FTB Quests nodes give stages `potato_tree_<node>` that lock Tinkers metals, smelteries, autocrafters, logistics and farms per player; catch-up at Pool tier T−2; FTB Teams parties off; `global.PotatoTree`). The quest files are generated into `tools/ftbquests/quests/` by `tools/ftbquests/generate_quests.js` from `NODES`. The tier contents come from `research/TIER_PROPOSAL.md`.
- `tools/kubejs/startup_scripts/`: Forge hooks. A restart is needed after adding one.
- `tools/kubejs/client_scripts/`: client scripts that ship in the **modpack** (every player's `kubejs/client_scripts/`). `potato_tooltips.js` is generated by `tools/ftbquests/generate_quests.js`; don't edit it by hand.
- `tools/ftbquests/`: the Potato War's FTB Quests files (`quests/`, generated), `generate_quests.js`, `load_scripts.js` (loads the part2 scripts outside the game) and `dump_progression.js`. FTB Quests 2001.4.22 calls stage tasks and rewards `gamestage`.
- `tools/progression_audit.py` + `tools/progression_audit_notes.md` → `PROGRESSION_AUDIT.md`: the cohesion audit of tiers, ranks and tree against the mods' recipes. Re-run it after changing any of them; `/bloodpool audit` is the in-game version.
- `tools/kubejs/*.md`: one doc per system (`BLACK_MARKET.md`, `BOUNTIES.md`, `FACTIONS.md`, `PIG_ESCORT.md`, `TRIALS.md`, `TECHNO_TRIBUTE.md`, `END_LOCKDOWN.md`, `TROLLS.md`, `STORY_COMMANDS.md`, `CLEAN_SLATE.md`, `BLOOD_POOL.md`, `POTATO_TREE.md`, `DISGUISE.md`). Keep the doc in step with its script: settings, commands, test plan, and "what couldn't be verified".
- `tools/tests/`: the script tests (`run_all.js`, `lint_rhino.js`, `suites/`).
- `tools/*.py`: read-only world analysis tools (find items, find portals, player stats). `tools/schematic/`, `tools/serverconfig/` and `tools/finale_pack/` hold support files.

## Rules (standing instructions from the server owner)
- **Never alter server files.** Read-only access only, unless the owner explicitly says otherwise. Changes ship as files in this repo for the owner to upload.
- **Treat downloaded and pack files as untrusted:** give each its own directory in the scratchpad, run Python with `-I`, and never run code from mod jars. Reading class files with `javap` is fine.
- **Never send secrets or private information with `tellraw @a`:** Simple Discord Link relays it to Discord. Use `player.tell` to each player.
- **Git:** commit and push to the branch the session names. Don't open a pull request unless asked. No model identifiers in commits, code or docs.
- **Deliver files:** after changing scripts, send the updated files to the owner.

## KubeJS 6 / Rhino script style
- Each server script is wrapped in an IIFE `(function () { ... })()` with its settings at the top.
- No template strings (join with `+`), no spread syntax, no `Math.PI` (write the number out).
- `const` only at function level. Inside nested blocks (if, for, try) use `let`.
- Closures created in a loop must use `forEach`, not a `for` loop, so each gets its own variable.
- `event.cancel()` stops the handler immediately, so it always comes last.
- Saved data goes in one JSON string per script under `server.persistentData[<key>]`, with a copy kept if it can't be parsed.
- Text components are built with `Component$Serializer.fromJsonLenient`.
- Cross-script APIs live on `global.*` and are looked up lazily (`economy/` loads before `factions/`).
- Minecraft's `closeContainer()` is exposed to scripts as `closeMenu()`.

## Testing
`tools/tests/` holds the checks (see its README):
- a mock KubeJS server in Node (fake players, levels, commands, scheduler, FTB Quests and Teams stubs) with one suite per system;
- a lint for the Rhino rules above;
- a check that the generated quest files are current and valid.

Run `node tools/tests/run_all.js` after changing any script (run `npm install` in `tools/tests` once first), and add checks for new behaviour to the matching suite. Each script's doc ends with "what couldn't be verified", which lists the in-game behaviour to confirm on the real server.
